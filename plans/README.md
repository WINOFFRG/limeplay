## Decisions for the maintainer (not plans)

1. **The pro submodule is not a paid tier.** Given that, three pieces of
   machinery exist only to protect something that is not secret: the private
   submodule plus two clone tokens (CI and Vercel), the `/r/pro/:path*` → `/403`
   redirect in `apps/www/vercel.json`, and the free/pro split in
   `apps/www/scripts/registry-dev.mts`. Moving `registry/pro` into the main
   repository would remove both tokens, most of plan 002, and the reason fork
   PRs cannot run the full CI. Until then, plan 002 still applies.
2. **Pro components are not installable.** No item in
   `apps/www/registry/collection/*` has `categories: ["pro"]`, so
   `MediaAmbient`, `MediaGlow`, `AmbientPlayer` and `ImmersivePlayer` are in no
   registry and have no docs page. A stale local `apps/www/registry-pro.json`
   (gitignored) still makes local builds emit `public/r/pro/*`. Decide whether
   to register them (then they need docs and metadata) or leave them parked.
3. **Who owns `media.loop`?** `use-playlist.ts:813-817` sets
   `mediaElement.loop = repeatMode === "one"` on every repeat-mode change,
   overriding `<video loop>` and `playback.setLoop(true)` while
   `playback.loop` still reads the old value. Either derive
   `media.loop = playback.loop || repeatMode === "one"` in one place, or
   implement repeat-one in the `ended` handler. Needs a decision, then a small plan.
4. **Third-party registry dependency.** `video-player`, `audio-player` and four
   examples declare `https://bazza.dev/r/hit-area` as a registry dependency, so
   every install pulls source from another host with no version or integrity
   check. Vendoring it (with attribution) removes that.

## Direction (options, not plans)

Each is grounded in something already in the repo; effort estimates are coarse.

- **Fullscreen + keyboard shortcuts** (M). `prompts/ide.md` requires "Space,
  Enter, Arrow keys, M, F"; there is no fullscreen code and no key binding in
  `registry/default`, while five controls already accept a `shortcut` prop that
  only sets `aria-keyshortcuts`. `use-picture-in-picture.ts` is a ready template
  for a `fullscreenFeature`.
- **Quality and audio-track selection** (M each). README advertises adaptive
  bitrate; nothing calls `getVariantTracks` / `selectVariantTrack`.
  `use-captions.ts` and `ui/playback-rate.tsx` are close patterns.
- **Live / DVR UI** (S–M). `isLive` and live-relative maths exist in
  `use-timeline.ts` and `ui/timeline-control.tsx`, and the video block's default
  demo source is a live stream, but there is no LIVE badge or seek-to-live control.
- **Media session as a first-class feature** (M). It is the most-iterated area
  (last three commits) and lives in two near-identical per-block controllers
  (`blocks/*/components/media-session-controller.tsx`). A shared controller
  would also give custom-player users lock-screen support.

## Audit findings not yet planned

Reported by audit sub-agents with code references, but not verified
line-by-line by the plan author, or needing a design decision first. Re-audit
before planning.

- Playback status machine: `canplay` / buffering-end handlers can overwrite the
  `error` status; `ended` is not reset on replay; some transitions skip the
  `statuschange` event (`use-playback.ts:250-334`, `use-player.ts:335-350`).
- Preload bookkeeping in `use-asset.ts`: managers captured before awaits and
  written back stale (`:461-465`, `:505-511`), not destroyed when bypassed by
  `resolveSource`, not cleared on player teardown; playlist ids
  (`:1127-1130`) and load/preload ids (`:436-438`, `:647-649`) are computed
  with different arguments.
- Caller-owned asset and `loading` objects are frozen by Immer after
  `loadSource` / `loadPlaylist`.
- Timeline drag seeks on every pointer move (`ui/timeline-control.tsx:91-93`).
- Video error screen may be stacked under the video (`z-10` vs `z-20`);
  needs a visual check with a failing source.
- Audio block `fetchPlaybackUrl` throws on relative URLs (`new URL(x)` with no base).
- Safari picture-in-picture events may fire twice.
- Agent instruction files (`prompts/*.md`, `.github/copilot-instructions.md`,
  `.cursorrules`, `.github/instructions/*`) repeat the same lists in about five
  places and already lag the code (they say 18 events; 25 exist; media session
  and the exclusive playback provider are missing). No `AGENTS.md` exists.
- `DEVELOPMENT.md` setup: `bun run dev` on a fresh clone may fail until
  `registry:build` has generated `registry/__index__.tsx`.
- Lefthook runs `eslint --fix` and `prettier --write` in parallel without
  `stage_fixed`, so fixes are not added to the commit.
- TypeScript 6 at the repo root vs TypeScript 7 in `apps/www`; type-aware lint
  rules and `tsc` use different compilers.
- Duplicate lodash styles in shipped code (`lodash/clamp` vs `lodash.clamp`).

## Findings considered and rejected

- Lefthook vs ESLint config mismatch: not real — ESLint resolves the nearest
  config per file, so running from the root applies `apps/www/eslint.config.mjs`.
- "Unused" dependencies (`react-use`, `date-fns`, `jotai`, `three`,
  `@react-three/*`, `beautiful-mermaid`, `@lottiefiles/dotlottie-react`,
  `schema-dts`): all have real imports. Only `@radix-ui/react-collapsible` has none.
- `vercel.json` mixing `routes` with `redirects`/`headers`: production deploys
  succeed with it and both behave correctly.
- Pro source exposure through `public/r/pro`: withdrawn — the maintainer
  confirmed pro is not a paid tier (see Decisions, item 1).
- Response-hardening headers (CSP etc.) for the docs site: low value for a
  static site with no auth or cookies; a CSP risks breaking third-party widgets.
- `bunfig.toml` `minimumReleaseAge` being ignored on Bun 1.2.19: unverified
  guess, not filed.
- Splitting `use-playlist.ts`: cohesive as is; only its pure helpers were
  exported for tests (plan 004).
- `.env.local`: untracked, gitignored, never committed. No secrets found in
  tracked files.
